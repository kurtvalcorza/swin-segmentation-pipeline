## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, repository import, worker process or subprocess (the generator-owned install cell excepted). Section 2 carries `src/dimer_swin_segmentation/metrics.py`, `src/dimer_swin_segmentation/samples.py`, and `src/dimer_swin_segmentation/runtime.py` verbatim, in dependency order (each tagged `metadata.dimer.embedded_module`; the rewrites make the default weights directory working-directory-relative and drop package-relative imports), Section 3 carries the model identity and the 1-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `tools/pins.txt` runtime pins including the PyTorch CPU index and the OpenMMLab mmcv find-links. `metadata.dimer.generated_from` records the repository, the generating revision, module paths, their joined SHA-256, and the generator version.
- **Qualified runtime (ENV2/ENV4):** CPython 3.10 with torch 2.1.2+cpu, MMCV 2.1.0, MMEngine 0.10.7, MMSegmentation 1.2.2, NumPy 1.26.4 (plus `ftfy`/`regex`, MMSegmentation's text dependencies). `pip` cannot pin the interpreter, so the requirement is stated in Prerequisites and asserted (`sys.version_info[:2] == (3, 10)`) in Section 4; the carried `verify_runtime_versions` fails closed on OpenMMLab version drift. Default Colab/Kaggle runtimes (Python 3.11+) are unsupported.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition and trust boundary (MOD12–MOD14):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the absent checkpoint from the pinned `download.openmmlab.com` URL (the manifest's single entry; the model host is not the Hugging Face Hub and the `MODEL_REVISION` is the MMSegmentation `v1.2.2` release-tag commit that is the config source); `verify_snapshot` re-hashes it against the manifest **and** `MODEL_SPEC`; `from_pretrained(weights_dir=WEIGHTS_DIR)` then lets the pinned MMSegmentation loader deserialize the code-capable `.pth` (upstream's `mmengine` load, not `weights_only`). The notebook states that the digest proves byte identity, not publisher authenticity.
- **Role stages:** `validate_dataset` (DAT24) writes `outputs/swin_segmentation_input_manifest.json` with the schema, record counts, class names, verdict, and one recorded rejection finding (empty-dataset probe); `evaluate` (EVAL21) writes `outputs/swin_segmentation_evaluation_report.json` with `semantic_iou` (mean IoU over classes present, pixel accuracy, per-class IoU) and the `majority_class_baseline`.
- **Samples & Adaptation:** the default sample is deterministic in-code synthetic data (no network download): one 512×384 scene for pretrained demonstration, and 24 scenes with pixel masks for 3-class adaptation (`background`, `road`, `structure`).
- Segmentation obligations: the class count and pixel ceiling are surfaced before the model runs, the output is described as a per-pixel argmax with no exposed confidence and no shipped threshold, masks are exported as PNG class-index rasters, and the per-image class coverage is written as CSV ordered by coverage.
- `USE_BYOD_IMAGE` and `USE_BYOD_DATASET` default to `False` so the sample path never opens an upload dialog or downloads data.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
