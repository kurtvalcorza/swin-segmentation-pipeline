## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, repository import, worker process or subprocess (the generator-owned install cell excepted). Section 2 carries `src/dimer_swin_segmentation/metrics.py` and `src/dimer_swin_segmentation/runtime.py` verbatim, in dependency order (each tagged `metadata.dimer.embedded_module`; the rewrites make the default weights directory working-directory-relative and drop the one package-relative import), Section 3 carries the model identity and the 1-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `tools/pins.txt` runtime pins including the PyTorch CPU index and the OpenMMLab mmcv find-links. `metadata.dimer.generated_from` records the repository, the generating revision, both module paths, their joined SHA-256, and the generator version.
- **Qualified runtime (ENV2/ENV4):** CPython 3.10 with torch 2.1.2+cpu, MMCV 2.1.0, MMEngine 0.10.7, MMSegmentation 1.2.2, NumPy 1.26.4 (plus `ftfy`/`regex`, MMSegmentation's text dependencies). `pip` cannot pin the interpreter, so the requirement is stated in Prerequisites and asserted (`sys.version_info[:2] == (3, 10)`) in Section 4; the carried `verify_runtime_versions` fails closed on OpenMMLab version drift. Default Colab/Kaggle runtimes (Python 3.11+) are unsupported.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition and trust boundary (MOD12–MOD14):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the absent checkpoint from the pinned `download.openmmlab.com` URL (the manifest's single entry; the model host is not the Hugging Face Hub and the `MODEL_REVISION` is the MMSegmentation `v1.2.2` release-tag commit that is the config source); `verify_snapshot` re-hashes it against the manifest **and** `MODEL_SPEC`; `from_pretrained(weights_dir=WEIGHTS_DIR)` then lets the pinned MMSegmentation loader deserialize the code-capable `.pth` (upstream's `mmengine` load, not `weights_only`). The notebook states that the digest proves byte identity, not publisher authenticity.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/swin_segmentation_task_inference_input_manifest.json` with the schema, ceiling (`MAX_PIXELS` 64,000,000), per-input observations, verdict, and one recorded rejection finding (missing-file probe); `evaluation_report` (EVAL21) writes `outputs/swin_segmentation_task_inference_evaluation_report.json` — `not-measurable` on the synthetic sample (with what labelled data would make the task measurable), `sample-sanity` with `semantic_iou` (mean IoU over classes present, pixel accuracy, per-class IoU) and the `majority_class_baseline` when `USE_ADE20K_FIXTURES` is enabled.
- **Samples:** the default sample is a deterministic 512×384 synthetic scene generated in code (no download, no ground truth); its mask is sanity evidence for the input contract and forward pass, not a correctness or benchmark claim. `USE_ADE20K_FIXTURES` (off by default) fetches `ADE_val_00000001` / `ADE_val_00000002` (JPEG + PNG annotation each) from `hf-internal-testing/fixtures_ade20k` at the immutable commit `850d349e5038f291284e7999fcacbedc0922534b`, refuses any file whose SHA-256 differs from the recorded digests, and converts the raw annotations with the carried `ade20k_raw_to_indices` (`reduce_zero_label` convention of the pinned config); no split is invented or changed.
- Segmentation obligations: the class count (150) and pixel ceiling are printed before the model runs, the output is described as a per-pixel argmax with no exposed confidence and no shipped threshold, masks are exported as PNG class-index rasters, and the per-image class coverage is written as CSV ordered by coverage.
- `USE_BYOD` and `USE_ADE20K_FIXTURES` default to `False` so the sample path never opens an upload dialog or downloads data.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`. The previous Notebook Specification 1.0 notebook's clean run of 2026-09-11 (mIoU `0.387` on the two fixtures) is retained there as an audit trail for the replaced carrier only.
